# 5발을 쐈는데 2발만 나가는 이유 — 이교수 사방 청진기 + 난이도 손보기

## 한 줄로

이교수가 청진기를 **사방으로 5발** 흩뿌리게 만들었는데, 처음엔 2발만 나갔어. 알고 보니 "동시에 떠 있을 수 있는 청진기는 2개까지"라는 **정원 제한(=2)** 에 막힌 거였어. 정원을 8로 늘리니 5발이 다 나갔지. 그리고 이교수를 **플레이어 정반대편**에서 시작하게 해 "시작하자마자 맞는" 문제를 없애고, 중난이도도 **F가 벽을 통과**하게 해 살짝 더 어렵게, 시작 버튼은 글자에 더 **바짝** 붙였어.

## 문제 1 — 사방으로 던지기: "한 방향"을 "여러 각도"로

원래 이교수는 청진기를 **플레이어가 있는 쪽 한 방향**으로만 던졌어. 이걸 "여러 방향"으로 바꾸는 건 생각보다 간단해.

- 먼저 플레이어가 있는 **각도**를 구해(이게 `atan2` — "그 점이 나로부터 몇 시 방향이냐"를 알려주는 함수).
- 그 각도를 시작점으로, **360° ÷ 5 = 72° 간격**으로 5개의 각도를 만들어.
- 각 각도마다 청진기를 하나씩, 그 방향으로 날려.

시계로 치면 12시(플레이어 쪽)에서 시작해 72°씩 돌아가며 5방향(대충 12시·2시 반·5시·7시 반·10시)으로 동시에 뿌리는 거야. 하나는 꼭 플레이어를 향하니 위협적이고, 나머지는 사방을 덮어 피할 길을 좁혀.

> **Spring 비유**: 받는 쪽(target)을 하나 정해 1건 보내던 걸, **수신자 목록(List<angle>)을 만들어 반복문으로 N건 보내는** 걸로 바꾼 거야. `for (recipient : recipients) send(...)` 패턴. 핵심 로직(만들고 → 방향 정하고 → 날린다)은 그대로고, **단건 → 다건(배치)** 으로만 바뀐 거지.

## 문제 2 — "5발 쐈는데 2발만?" 정원 제한의 함정

다발로 바꿨는데 화면엔 2발만 떴어. 코드에 이런 문지기가 있었거든:

> "지금 떠 있는 청진기가 **2개 미만일 때만** 새로 던져라." (과밀 누적 방지용)

5발을 쏘는 순간 화면엔 5개가 생기는데, 정원이 2라서… 사실은 던지기 사이클 자체가 "2개 미만일 때만" 시작되니, 한 번 5개가 뜨면 다음 사이클이 한참 막혀. 그래서 **정원을 8로** 늘렸어(5발 + 직전 잔여분 여유).

> **Spring 비유**: 딱 **커넥션 풀 / 세마포어 / 스레드풀 maxPoolSize** 이야기야. `maxPoolSize=2`인데 동시에 5개 작업을 밀어넣으면 2개만 돌고 나머진 막히지. 처리량을 늘리려면 **풀 크기를 늘려야** 해. 단, 문지기를 *없애면* 안 돼 — 그럼 청진기가 무한 누적(메모리 누수)되니까. **값만 올리고 가드는 유지**가 핵심.

참고로 청진기는 벽에 닿으면 사라지게 돼 있어서(통과는 하되 "닿았다" 신호로 제거), 8개로 늘려도 금방금방 정리돼 쌓이지 않아.

## 문제 3 — 이교수를 "정반대편"에 세우기 (점대칭)

"시작하자마자 청진기에 맞는다"는 건 이교수가 플레이어랑 너무 가까이서 시작한다는 뜻이었어. 그래서 이교수를 **플레이어의 정반대편**에 세웠어.

- 플레이어는 맵 왼쪽 가운데 (200, 250)에서 시작. 맵은 800×500이라 한가운데가 (400, 250).
- 정반대 = 한가운데를 기준으로 **거울처럼 뒤집은 점** = (800−200, 500−250) = **(600, 250)**, 오른쪽 가운데.

수식으로는 `(맵가로 − 플레이어x, 맵세로 − 플레이어y)`. 이게 "중심을 기준으로 한 점대칭"이야. 최대한 멀리 떼어놓는 거지.

> **Spring 비유**: 그냥 좌표 산수라 비유랄 게 크진 않은데… 굳이 들면 **데이터를 중심값 기준으로 미러링**하는 변환 한 줄이야.

### 곁들인 함정 — "같은 이름의 메서드, 다른 반". 하나만 바꾸기

이교수·수간호사·석조무사 셋 다 `selectInitialWaypoint(시작위치 정하기)`라는 **똑같은 이름의 메서드**를 각자 갖고 있어. 이교수 것만 바꾸려다 셋 다 영향 줄 뻔했지. 그래서 기존 메서드는 그대로 두고, 이교수에만 **새 메서드(`spawnOpposite`)를 추가**해서 이교수 호출부만 갈아끼웠어. 수간호사·석조무사는 0줄도 안 건드렸어(grep으로 확인).

> **Spring 비유**: 인터페이스 하나에 구현체가 여럿일 때, **한 구현체만 바꾸고 나머지는 안 건드리는** 거랑 같아. 이름이 같다고 다 같은 게 아니야 — 각자 자기 클래스 안에 따로 있으니, 바꿀 놈에만 새 메서드를 더해주면 나머진 안전해.

## 문제 4 — 중난이도 살짝 어렵게 + 시작버튼 붙이기 (각 1줄)

- **중난이도 F 벽통과**: 난이도별 설정이 **한 곳의 표(딕셔너리)** 에 모여 있어서, `중: 안통과 → 통과`로 **한 칸만** 바꿨어. 쉬움·어려움은 그대로. 벽을 통과하면 화면에 쌓일까 걱정되지만, 이미 **3.2초 뒤 자동 소멸(수명)** 이 걸려 있어서 안전해.
- **시작버튼**: caption과의 간격 숫자(54)를 **18**로 줄여 바짝 붙였어. 식은 그대로, 숫자 하나.

> **Spring 비유**: 난이도 표는 `Map<난이도, 설정>` — **환경별 기능 플래그(feature flag)** 같은 거야. 한 키의 값만 토글. 그리고 "3.2초 후 자동 소멸"은 캐시의 **TTL(만료시간)**, Redis `EXPIRE` 같은 거지 — 안 지우면 쌓이니까 시간 지나면 알아서 비워.

설계자 → 구현자 → 검수자. 검수 **합격 9.15/10**, 빌드 `BUILD SUCCEEDED`. 구현자가 텔레그래프(경고선) 도구의 **실제 함수 모양**을 직접 읽고 거기에 맞춰 다방향 버전을 붙인 게 좋았어(설계서 스케치와 인자 이름이 달랐는데 실제에 맞춤). 끝나고 나도 grep으로 정원=8·정반대식·다른 적 미변경을 다시 확인했어.
