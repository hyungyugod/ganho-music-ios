## 1. U7 — D-Pad: "문턱 하나"로 두 마리 토끼

### 문제 복습

R10 스무딩은 손떨림은 잘 막았지만, 달리다가 방향을 꺾는 — 게임에서 제일 흔한 —
동작까지 80ms 늦게 만들었습니다. 스무딩을 빼면 떨림이 돌아오고, 두면 지연이 남는
딜레마였죠.

### 해법: 각도 게이트

두 벡터의 내적(dot product)은 "두 방향이 얼마나 비슷한가"를 숫자 하나로 알려줍니다.
같은 방향이면 1, 직각이면 0, 정반대면 −1. 그래서 문턱 하나만 세우면 됩니다:

```
지금 방향과 새 명령의 내적 < cos(60°) = 0.5  →  크게 꺾는 중 = 즉시 스냅
그 외(60° 미만의 미세 변화)                →  손떨림일 수 있음 = 부드럽게
```

Spring 비유: 요청을 전부 큐에 넣어 배치 처리(스무딩)하면 부하는 안정되지만 급한
요청도 늦어집니다. 해법은 **우선순위 조건 하나** — "긴급 플래그가 켜진 요청은 큐를
건너뛰어 즉시 처리". 배치의 장점(안정)과 즉시성(긴급)을 조건 분기 하나로 다 가져가는
구조가 똑같습니다.

디테일 둘:

- **cos(60°)을 미리 계산해 0.5로 박아뒀습니다.** 매 프레임(초당 60번) 삼각함수를
  부르지 않기 위해서요. Spring으로 치면 매 요청마다 설정 파일을 파싱하지 않고
  기동 시점에 `@ConfigurationProperties`로 한 번만 읽어두는 것과 같습니다.
- **보간 결과를 다시 길이 1로 펴줍니다(재정규화).** 두 방향의 중간값은 길이가 1보다
  짧아져서 — 꺾는 동안 캐릭터가 느려지는 부작용의 원인 — 매 프레임 길이를 복원하면
  방향은 부드럽게 돌되 속도는 항상 100%입니다.

그리고 약속 지키기: 이번 수정은 입력을 소비하는 쪽 파일 2개만 건드렸고, D-Pad
본체(DPadNode)·방향 모델(Direction)·플레이어(PlayerNode)는 **diff 0줄**입니다.
검수자가 git으로 직접 확인했습니다.

## 2. U8 — 게임을 멈추는 건 "한 줄"이 아니라 "세트"다

### 멈춤은 3종 세트

이 게임에서 "멈춤"은 스위치 하나가 아닙니다:

| 장치 | 멈추는 것 |
|---|---|
| gameState = .cutscene | 45초 타이머, 입력 처리, 적 AI (update 루프) |
| worldNode.isPaused | 월드 위 모든 애니메이션 (석조무사 순찰 등) |
| physicsWorld.speed = 0 | 날아가는 투사체 (물리 엔진) |

하나라도 빠뜨리면 "타이머는 멈췄는데 F탄은 날아오는" 반쪽 정지가 됩니다. 그래서
일시정지 메뉴가 쓰는 검증된 레시피를 **freeze/resume 헬퍼 쌍**으로 묶고, 복원은
정확히 역순으로 했습니다. 검수자가 6단계를 1:1 표로 대조했죠 — 한 단계라도
비대칭이면 영구 정지나 유령 입력이 생기니까요.

Spring 비유: 트랜잭션 시작과 커밋/롤백처럼, **잡은 자원은 반드시 역순으로 풀어야**
합니다. try-with-resources가 자원을 연 역순으로 닫아주는 것과 같은 규율입니다.

### planner가 찾아낸 숨은 함정 — "다른 시스템이 내 잠금을 풀어버린다"

설계 단계에서 planner가 P0급 구멍을 발견했습니다: 히트스톱(타격 시 0.015~0.12초
미니 정지) 시스템도 physicsWorld.speed를 만지는데, 기존 가드는 "일시정지 중"만
확인하고 **"컷씬 중"은 확인하지 않았습니다**. 컷씬으로 얼려둔 게임을, 히트스톱이
끝나면서 자기가 얼린 줄 알고 풀어버릴 수 있었던 거죠.

→ 가드 한 줄: "일시정지 **또는 컷씬** 중이면 히트스톱 요청 무시."

Spring 비유: 두 컴포넌트가 같은 락을 쓰는데 한쪽이 **자기가 잡은 락인지 확인 않고
unlock을 호출**하는 버그입니다. 락에는 소유권 검사가 필요합니다.

### 순서의 문제 — 공습은 "읽기 끝난 다음"

카메라에 붙은 연출은 월드를 얼려도 계속 돕니다(일시정지 다이얼로그가 살아 움직이는
것과 같은 원리). 그래서 공습(비행기·폭탄)을 컷씬과 동시에 시작하면 유저가 글을 읽는
동안 쇼가 뒤에서 혼자 끝나버립니다. 공습 호출을 **컷씬을 탭으로 닫은 콜백 안**으로
옮겼습니다 — `@TransactionalEventListener(AFTER_COMMIT)`처럼요.

### 잠자던 대사, 그대로 무대에

"사실 박병장은 석조무사의 오랜 친구입니다…" — 이 대사는 코드에 정의만 된 채 한 번도
안 쓰이고 있었습니다. 이번에 글자 하나 안 바꾸고(diff 0) 참조만 연결해 부활시켰습니다.
새 기능의 대사·멈춤 장치·컷씬 화면이 전부 기존 부품이라, 9파일 +164줄로 끝났습니다.

## 오늘의 교훈

1. **딜레마는 종종 "조건 하나"로 풀린다.** 스무딩 제거 vs 유지가 아니라, "언제
   스무딩할지"를 가르는 문턱(60°)이 정답이었다.
2. **멈춤/재개 같은 쌍 작업은 대칭표로 검증하라.** 6단계 freeze ↔ 6단계 resume을
   1:1로 대조하면 비대칭 버그가 표에서 바로 보인다.
3. **전역 상태를 만지는 시스템이 둘 이상이면 소유권을 의심하라.** 히트스톱이 컷씬의
   동결을 풀어버리는 함정은 코드를 짜기 전, 설계 단계의 추적에서 잡혔다.
4. **검수는 주장 재확인이 아니라 독립 재현.** evaluator가 빌드·수학·라이브
   라운드트립(동결→탭→재개)을 전부 자기 손으로 다시 했고, 그래서 합격에 무게가 있다.
