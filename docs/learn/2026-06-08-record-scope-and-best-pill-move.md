# 기록이 사라진 게 아니라 "다른 서랍"을 열고 있었다 + BEST 배지 자리 옮기기

## 한 줄로

**기록은 멀쩡히 쌓여 있었다 — 게임은 "내 계정 서랍"에 저장하는데, 기록 보기 화면이 "공용 서랍(빈 칸)"을 열고 있어서 안 보였을 뿐**이다. 기록 보기가 게임과 같은 서랍을 열게 바꾸니 그동안 쌓인 기록이 즉시 나타났다. 그리고 점수를 자꾸 가리던 BEST 배지는, 같은 세로줄에서 아무리 간격을 줘도 좁은 화면에선 도로 붙길래 **아예 다른 칸(우상단)으로** 빼버렸다.

## 문제 1 — 기록이 누적이 안 된다?

기록 보기 화면(캐릭터×난이도 최고점 표)에 아무리 플레이해도 기록이 안 쌓이는 것처럼 보였어. 그런데 코드를 까보니 **기록은 멀쩡히 저장되고 있었어.** 문제는 "어디에 저장하고, 어디서 읽느냐"였지.

### 핵심 개념 — "열쇠(key)가 다르면 다른 서랍이다"

이 게임은 기록을 **UserDefaults**라는 곳에 저장해. 이건 **"열쇠(문자열) → 값"** 으로 물건을 넣고 빼는 큰 서랍장이야. 열쇠가 같아야 같은 서랍을 열지.

- **게임(저장할 때)**: 열쇠 = `"perDifficultyScore.내계정ID"` ← 계정별 서랍
- **기록 보기(읽을 때)**: 열쇠 = `"perDifficultyScore"` ← 계정ID 없는 공용 서랍

열쇠가 다르니까 **저장은 A서랍에, 읽기는 B서랍에서** 한 거야. B서랍은 늘 비어 있으니 "기록이 안 쌓이네?"로 보인 거지. 기록이 사라진 게 아니라, **엉뚱한 서랍을 열고 있었어.**

> **Spring 비유** (이게 진짜 딱이야): **멀티테넌시(multi-tenancy)** 버그야! 데이터를 저장할 땐 `WHERE tenant_id = 'me'` 로 내 칸에 INSERT 했는데, 조회할 때 `tenant_id` 조건을 빠뜨리고 공용 테이블을 SELECT 하면 "어, 내 데이터가 없네?" 싶잖아. 행(row)은 분명히 있는데 **다른 키로 찾아서** 안 보이는 거야. 또는 Redis에 `user:123:score` 로 SET 해놓고 `score` 로 GET 하는 것과 똑같아. **키 접두사(prefix) 불일치.**

### 어떻게 고쳤나

기록 보기 화면이 게임과 **똑같은 열쇠**(계정ID 붙은 것)를 쓰게 한 줄 바꿨어:

```
// 전: 공용 서랍 (계정ID 없음)
let perDiffRepo = PerDifficultyScoreRepository()
// 후: 게임과 같은 계정 서랍
let scope = AccountProgressScopeProvider.current(...)   // 내 계정 알아내기
perDiffRepo = PerDifficultyScoreRepository.scoped(scope: scope)
```

데이터 이사(migration)도 필요 없었어. **이미 A서랍(계정 서랍)에 다 쌓여 있었으니까**, 읽는 열쇠만 A로 바꾸니 과거 기록이 한 번에 다 나타났어.

> 참고: "플레이 횟수(PLAYS 13)"는 왜 멀쩡했냐면, 그건 게임도 기록보기도 **둘 다 공용 서랍**을 쓰고 있었거든. 그래서 횟수만 정상이고 캐릭터별 최고점·졸업장만 안 보였던 거야. (이 미묘한 차이가 "일부만 누적 안 됨"의 정체였어.)

## 문제 2 — BEST 배지가 점수를 가린다

지난번에 "BEST 배지를 점수 아래로 충분히 내리기"로 고쳤는데, **좁은 가로 화면에선 또 붙었어.** 왜냐면 화면이 짧으면 "아래 통계랑 안 부딪히게" 하는 안전장치가 배지를 도로 위(점수 쪽)로 끌어올렸거든. 같은 세로줄에 셋(점수·배지·통계)을 욱여넣으니 자리가 모자랐던 거야.

그래서 네 말대로 **"아예 다른 위치"** — 점수가 있는 왼쪽 줄에서 빼서 **카드 오른쪽 위 구석**으로 옮겼어. 왼쪽 위엔 "상 난이도·임간호" 칩, 오른쪽 위엔 "🏆 BEST 78" — 양쪽 대칭이 됐지.

> **핵심**: 이제 점수는 **왼쪽 칸**, 배지는 **오른쪽 칸**이라 *수학적으로 절대 안 겹쳐.* 간격을 조절해서 "안 겹치게 비는" 게 아니라, **칸 자체를 분리**해서 겹칠 수가 없게 만든 거야.
>
> **Spring 비유**: 두 기능이 자꾸 충돌하면 같은 자원을 아슬아슬하게 나눠 쓰지 말고 **아예 책임(컬럼/모듈)을 분리**하는 거랑 비슷해. 경계를 명확히 그으면 충돌 자체가 구조적으로 불가능해져.

배치 후엔 **좌표로 검산**도 했어 — 큰 폰·작은 폰 둘 다 배지가 카드 밖으로 안 잘리고(우측 여백 80pt+), 아래 목표 글자랑도 30pt 넘게 떨어지는 걸 숫자로 확인.

## 어떻게 작업했나 (하네스)
