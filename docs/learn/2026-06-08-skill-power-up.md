# 스킬 강화 — 점수+생존 두 펀치 + 타격감, 매혹은 옷만 갈아입히기

## 한 줄로

**"북클럽 소집이 밍밍했던 건 효과가 음표 끌어오기 하나뿐이었기 때문"** 이다. 정·건·이간호 스킬에 **두 번째 펀치(음표 흡수 + F 폭발 정화)**를 달고 화면 흔들림·진동·2겹 충격파로 손맛을 입혔다. 임간호 매혹은 능력치는 한 글자도 안 건드리고 **발동 순간 화면 진동·이펙트만** 추가했다. 그리고 점수는 절대 직접 더하지 않았다 — 음표를 플레이어한테 끌어다 붙여 "자연스럽게 먹게" 했다.

## 무슨 문제였나

스킬을 써도 "뭐가 바뀐 거지?" 싶었어. 특히 건간호 **북클럽 소집**은 주변 음표를 끌어오는 것뿐이라, 주변에 음표가 없으면 민트색 링 한 번 반짝이고 끝 — 강력하다는 느낌이 0이었지.

## 각 스킬에 뭘 더했나

| 스킬 | 원래 | 추가한 "두 번째 펀치" + 타격감 |
|---|---|---|
| **정간호 · 돌진** | 4타일 돌진 + 경로 F 제거 + 짧은 무적 | ➕ 경로 음표 쓸어담기 ➕ 착지 시 둘레 F 원형 폭발 + 무적 살짝 연장 🎆 화면 흔들림 + 강한 진동 |
| **건간호 · 소집** | 8타일 음표 끌어오기 | ➕ 같은 범위 F 한 방에 정화(안전지대 폭발) ➕ A아이템도 흡수 🎆 2겹 충격파 링 + 강한 진동 + 카메라 펄스 |
| **이간호 · 대만여행** | 반대코너 순간이동 + 착지 F 제거 + 1초 무적 | ➕ 착지 주변 음표 흡수 ➕ 출발 지점 F도 정화 + 무적 1→1.6초 🎆 강한 진동 |
| **임간호 · 매혹** | F→A 변환, 점수 2배, 1회, 4초 | 🎆 **게임성 0 변경** — 화면 진동 + 2겹 링 + 진동만 |

쿨다운(20~22초)은 그대로 뒀어. "한 방이 세짐"이지 "더 자주 씀"이 아니라서 밸런스가 안 무너져.

## 핵심 개념 1 — "점수를 직접 더하지 마라" (단일 진실 원천)

이게 이번 작업에서 제일 중요한 규칙이었어. 스킬로 음표를 먹였으니 `점수 += 10` 하면 될 것 같지? **절대 안 했어.** 대신 음표를 플레이어 위치로 **끌어다 붙여서**, 평소 음표를 먹을 때랑 똑같은 길(충돌 감지 → 점수 처리)을 그대로 타게 했어.

> **Spring 비유** (이게 정확해): 계좌 잔액을 늘릴 때 `UPDATE account SET balance = balance + 1000` 으로 **컬럼을 직접 때리면** 안 되잖아. `account.deposit(1000)` 도메인 메서드를 불러야 거래내역 INSERT, 이벤트 발행, 한도 검증 같은 **딸려오는 처리가 다 같이** 일어나니까. 우리 게임도 똑같아. 음표 먹기 처리(`recordNoteHit`) 안에는 점수만 있는 게 아니라 **콤보 계산 + 콤보 마일스톤 팝업 + 효과음 + 진동**이 줄줄이 엮여 있어. 직접 `점수 +=` 하면 이게 다 빠져. 그래서 "정문(끌어오기→충돌)"으로만 들여보낸 거야.

게다가 실제로 `ScoreSystem`의 점수 변수는 `private(set)` — **바깥에서 못 고치게 막혀 있어**. Spring의 setter 없는 도메인 객체랑 같아. 구조적으로 직접 조작이 불가능하게 설계돼 있던 거지.

## 핵심 개념 2 — DRY: 같은 코드를 세 군데 복붙하지 않기

세 스킬이 모두 "주변 음표를 끌어온다"를 하잖아. 그럼 끌어오는 코드를 세 번 복붙? ❌ 원래 북클럽 전용이던 끌어오기 함수를 **이름만 중립적(`pullCollectible`)으로 바꿔서 셋이 공유**하게 했어.

> **Spring 비유**: 세 컨트롤러가 같은 로직을 쓰면 각자 복붙하지 않고 `@Service`(또는 공용 유틸) 하나로 빼서 주입받지. 똑같은 거야. 한 군데만 고치면 셋 다 고쳐지니 버그도 줄어.

## 핵심 개념 3 — 매혹은 "옷만 갈아입히기" (관심사 분리)

임간호 매혹은 "능력치 건드리지 말고 이펙트만"이 요구였어. 그래서 **게임 로직 코드는 한 줄도 안 건드리고**, 그 아래에 화면 진동·링·진동 호출 3~4줄만 얹었어. 점수 2배·1회·4초 같은 숫자는 그대로.

> **Spring 비유**: 서비스 로직은 안 바꾸고 **AOP로 로깅/모니터링만 덧입히는 것**, 또는 API 응답 본문은 그대로 두고 **헤더만 추가**하는 느낌. "동작(business)"과 "보여주기(presentation)"를 분리해서, 보여주기만 손댄 거야. 그래서 매혹은 `git diff`에서 게임 숫자가 **0줄** 바뀌었어.

## 작은 함정 — 두 곳이 같은 숫자를 봐야 한다 (이간호 무적)

이간호 무적을 1초 → 1.6초로 늘렸는데, 무적 시간이 **두 군데**에 적혀 있었어:
1. 깜빡임 애니메이션 길이 (SkillSystem)
2. 스킬 진행바가 "끝났다"고 판단하는 길이 (PlayerSkill)

이 둘이 **다른 숫자를 보면** 무적은 끝났는데 깜빡임은 계속되거나, 진행바만 먼저 차는 어긋남이 생겨. 그래서 **둘 다 같은 상수 하나(`taiwanTripInvulnerableDurationV2`)를 보게** 통일했어.

> **Spring 비유**: 만료 시간을 프론트랑 백엔드가 각자 하드코딩하면 어긋나잖아. `application.yml`의 값 하나를 양쪽이 참조하게 하는 것 — 단일 설정값으로 통일.

## 작은 함정 2 — A아이템은 끌어오기 전에 "멈춰" 세워야 한다

음표는 제자리에서 까딱이지만, A아이템은 **물리 속도로 날아다녀**. 그래서 그냥 끌어오면 "물리 엔진이 미는 힘"과 "내가 끌어당기는 위치"가 서로 싸워서 부들부들 떨려. 끌어오기 직전에 `velocity = .zero`로 **속도를 0으로 세워두고** 끌어왔어.

## 어떻게 작업했나 (하네스)

설계자(Planner) → 구현자(Generator) → 검수자(Evaluator). 검수 결과 **합격 9.1/10**, 빌드 성공. 중간에 내가 매혹 게임성 0줄·무적 정합·카메라 진동 1회·점수 직접조작 0건을 직접 한 번 더 검증했어.

## 손댄 파일

- `Systems/SkillSystem.swift` — 4개 스킬 본체 + 끌어오기 공용 헬퍼
- `Models/PlayerSkill.swift` — 이간호 무적 길이 통일 + 스킬 설명문 갱신
- `Config/GameConfig.swift` — 새 숫자 9개를 상수로(매직넘버 0)

## 한 줄 교훈

**"효과를 더하라"고 점수를 직접 더하지 마라.** 게임이든 백엔드든, 결과(점수·잔액)는 항상 "정문(도메인 메서드)"으로만 바꿔야 딸려오는 처리가 안 빠진다.
