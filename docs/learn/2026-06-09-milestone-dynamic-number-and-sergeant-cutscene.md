# 고정 문구를 "살아있는 숫자"로 + 박병장 등장에 진동·이펙트 입히기

## 한 줄로

"절반 왔어요!"라는 **붙박이 문구**를, 난이도 목표에서 지금 점수를 뺀 **실시간 남은 개수**로 바꿔서 하드면 "20개만 더 모아봐요!"처럼 뜨게 했어(목표가 난이도마다 다르니 숫자도 알아서 달라져). 그리고 밋밋하게 떴다 사라지던 박병장 등장 컷씬에 **진동 + 화면 흔들림 + 번쩍임 + 반짝이**를 입혔는데, **기존 연출 타이밍은 한 글자도 안 건드리고** 위에 얹기만 했어.

## 문제 1 — "절반 왔어요!"를 숫자로

원래는 절반 지점에서 그냥 "절반 왔어요!"라는 **고정된 문장**이 떴어. 네가 원한 건 "20개만 더 모아봐요!"처럼 **남은 개수가 숫자로** 나오는 거였지.

핵심은 이거야: 그 숫자를 어디서 가져오느냐. **목표 점수 − 지금 점수 = 남은 개수**. 목표 점수는 난이도별 표(`targetScoreByDifficulty`)에 들어있어서:

- 하드(목표 40) → 절반(20점)에서 남은 건 40−20 = **20** → "20개만 더!"
- 이지(목표 70) → 절반(35점)에서 남은 건 **35** → "35개만 더!"

그래서 **코드는 한 벌인데 난이도마다 다른 숫자**가 나와. 문구도 `"절반 왔어요!"`(고정) 대신 `"개만 더 모아봐요!"`(꼬리말)만 상수로 두고, 앞에 숫자를 실시간으로 붙였어.

> **Spring 비유**: 고정 문자열을 **메시지 템플릿**으로 바꾼 거야. `messages.properties`에 `milestone.half={0}개만 더 모아봐요!` 두고 `{0}`에 값 꽂는 i18n 메시지처럼. 그리고 숫자가 난이도마다 자동으로 달라지는 건 **설정 기반(config-driven)** 이라 그래 — 같은 코드가 현재 컨텍스트(난이도)의 설정값을 읽어 다른 결과를 내는 거지. (지난번에 배운 "단일 진실의 원천"이 또 일해줬어.)

> 참고: "절반"은 "개", "10점 남음"은 "점"으로 단위가 살짝 달라. 네가 절반 쪽만 바꿔달라고 해서 그쪽만 손댔고, 10점 쪽은 그대로 뒀어. 통일하고 싶으면 말해줘 — 5초면 돼.

## 문제 2 — 박병장 등장을 "사건"으로 만들기

박병장 등장은 원래 화면이 살짝 어두워지고 얼굴이 떴다 사라지는 **조용한 컷씬**이었어. 네가 원한 건 (1) 멘트 바꾸고 (2) 진동 (3) 이펙트 더, 였지. 그래서 네 개를 얹었어:

- **멘트**: "석조무사가 친구인 박병장을 불러 유저를 도와줍니다!"
- **진동**: 묵직한 햅틱(heavy)을 짧은 간격으로 두 번 — "쿵쿵".
- **화면 흔들림**: 카메라를 잠깐 떨리게(이미 돌진에서 쓰던 효과 재활용).
- **번쩍임 + 반짝이**: 풀스크린 플래시 한 번 + 얼굴 주위로 반짝이 8방향 방사(둘 다 이미 있던 효과 재활용).

### 핵심 비결 — "기존 건 안 건드리고 위에 얹기"

가장 신경 쓴 건, **원래 컷씬 타이밍(2.2초)과 끝날 때 호출하는 콜백을 절대 안 건드린 것**이야. 이펙트는 전부 컷씬 위에 *추가*로 깔았고, 각자 0.5초 안에 알아서 사라져서 2.2초 안에 끝나. 만약 타이밍을 건드렸으면 "컷씬 끝나면 진짜 박병장 등장" 같은 뒤 흐름이 줄줄이 어긋났을 거야.

> **Spring 비유**: **기존 메서드 본문은 그대로 두고 바깥에서 부가기능만 두르는** AOP advice 같은 거야. 비즈니스 로직(컷씬 코어)은 안 만지고, 로깅·메트릭(이펙트·진동)을 `@Around`로 감싸 추가하는 거지. 그리고 효과는 새로 만들지 않고 **이미 있던 컴포넌트(흔들림·플래시·반짝이)를 재사용**했어 — 바퀴를 다시 발명하지 않기.

### 곁들인 함정 2개

1. **진동 두 번을 Timer 없이**: "0.12초 간격으로 두 번 진동"을 옛날식 `Timer`로 하면 게임이 멈춰도 따로 돌아 사고 나. 대신 게임 엔진의 액션(`SKAction.sequence([진동, 잠깐기다림, 진동])`)으로 했어. 게임이 멈추면 같이 멈추고, 끝나면 알아서 정리돼.
   > **Spring 비유**: `Thread.sleep` + 수동 스레드 대신 **스케줄러에 선언적으로 맡기는** 거랑 같아. 생명주기를 프레임워크가 관리해주니 누수·꼬임이 없어.

2. **긴 문장이 화면 밖으로 안 나가게**: 새 멘트는 길어서 한 줄로는 화면을 넘쳐. 그래서 "여러 줄 허용 + 최대 폭 지정 + 단어 단위 줄바꿈" 3종 세트를 걸었어.
   > **Spring 비유**: CSS의 `max-width` + `word-wrap` 같은 거야. 최대 폭을 안 정하면 글자가 상자 밖으로 삐져나가지.

## 짚고 넘어갈 점 — 멘트의 앞뒤가 안 맞아

네가 준 멘트 그대로 넣긴 했는데, 살짝 모순이 있어서 알려줄게:
- **석조무사는 쉬움/보통에만** 나오고 **박병장은 어려움에만** 나와. 그래서 박병장이 뜨는 어려움 화면엔 사실 석조무사가 없어.
- 박병장은 **여전히 폭탄 던지는 적**이야(행동은 안 바꿨거든). 근데 멘트는 "도와줍니다"라 실제 행동과 반대야.

멘트는 네 말대로 그대로 뒀어. "박병장을 진짜 도우미로 바꿀지" 아니면 "멘트를 손볼지"는 네가 정해줘 — 어느 쪽이든 다음에 해줄 수 있어.

## 어떻게 작업했나 (하네스)

설계자 → 구현자 → 검수자. 검수 **합격 9.35/10**, 빌드 `BUILD SUCCEEDED`. 끝나고 이름 바꾼 상수를 가리키던 낡은 주석 한 줄도 정리했어.

## 손댄 파일

- `GameScene.swift` — 절반 마일스톤을 "남은 개수 + 꼬리말"로 동적 조립
- `Config/GameConfig.swift` — 절반 꼬리말 상수 + 박병장 멘트/폰트/줄바꿈폭 상수
- `GameScene+Setup.swift` — 박병장 컷씬에 멘트·진동·흔들림·플래시·반짝이 추가
- `Nodes/MilestoneBannerNode.swift` — 낡은 주석 정리(1줄)

## 한 줄 교훈

**기존 흐름에 무언가 "더하고" 싶을 땐, 원래 타이밍을 건드리지 말고 위에 얹어라.** 코어를 안 만지고 바깥에서 감싸면(AOP처럼), 뒤따르는 흐름이 안 깨진다.
