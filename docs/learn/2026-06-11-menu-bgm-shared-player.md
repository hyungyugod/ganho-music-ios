# 메뉴 대기 BGM — 화면을 옮겨도 음악이 안 끊기는 비밀 (2026-06-11)

## 무엇을 만들었나

게임 안에서만 나오던 음악을, 이제 **메인 화면과 선택 화면에서도** 나오게 했다.
그것도 잔잔한 전용 곡(`menu_bgm.m4a`, 84 BPM)으로. 메뉴 화면을 아무리 오가도
음악이 한 번도 끊기거나 처음부터 다시 시작하지 않는다.

## 핵심 아이디어 1 — "씬이 죽어도 살아남는" 공유 플레이어

SpriteKit의 화면(씬)은 다른 화면으로 넘어가면 통째로 버려진다.
만약 각 화면이 자기 음악 플레이어를 들고 있으면, 화면이 바뀔 때마다
플레이어도 같이 버려져서 음악이 뚝 끊긴다.

해법: 플레이어를 화면 **바깥**에 둔다.

```swift
static let menuShared = BGMPlayer(resourceName: FeelTuning.bgmTrackNameMenu)
```

`static let`은 앱 전체에 딱 1개만 존재하는 물건이다. 화면이 100번 바뀌어도
이 플레이어는 그대로 살아 있다.

**Spring 비유**: 화면(씬)은 요청마다 새로 만들어지는 request scope 객체이고,
`menuShared`는 싱글톤 `@Service` 빈이다. 요청이 끝나도 빈은 살아 있는 것과 같다.

## 핵심 아이디어 2 — "이미 틀고 있으면 아무것도 안 한다" (멱등)

화면을 옮길 때마다 라우터(SceneRouter)가 `play()`를 부른다. 그럼 매번 곡이
처음부터 다시 시작될까? 아니다. `play()` 안에 이런 한 줄이 있다:

```swift
if player.isPlaying { return }   // 이미 재생 중이면 아무것도 안 함
```

"이미 켜져 있는 불은 또 켜지 않는다." 그래서 화면을 4번 옮겨도 음악은 1번만
시작된다. 이런 성질을 **멱등(같은 요청을 여러 번 해도 결과가 같음)**이라 부른다.
Spring에서 같은 PUT 요청을 두 번 보내도 결과가 같아야 한다는 그 원리다.

## 핵심 아이디어 3 — 출입구를 한 곳으로 (단일 훅)

메뉴 화면이 6개나 되는데, 6곳에 전부 "음악 켜기" 코드를 넣었을까? 아니다.
모든 화면 전환이 지나가는 **단 하나의 문**인 `SceneRouter.present()`에만 넣었다.

- 메뉴 화면으로 가면 → `menuShared.play()` (이미 재생 중이면 무시)
- 게임으로 들어가면 → `menuShared.stop()` (1초 페이드 아웃)

**Spring 비유**: 컨트롤러 6개에 같은 코드를 복붙하는 대신, 모든 요청이 지나가는
**인터셉터(HandlerInterceptor) 1개**에 넣은 것과 같다.

단 하나의 예외: 앱이 막 켜질 때의 첫 화면은 라우터를 거치지 않아서,
StartScene이 등장할 때 `play()` 1줄을 따로 불러준다 (부팅 시동 걸기).

## 핵심 아이디어 4 — 두 곡이 자연스럽게 교대하는 법

게임에 들어갈 때: 메뉴 곡은 1.0초에 걸쳐 작아지고, 인게임 곡은 1.5초에 걸쳐
커진다. 두 플레이어가 잠깐 동시에 소리를 내는데, iOS가 알아서 섞어준다
(크로스페이드). 별도 코드가 필요 없다.

## 설정은 스위치 하나로

"배경음악 끔" 설정은 예전 키(`settings.bgmEnabled`) 하나를 메뉴 곡과 인게임 곡이
**같이** 본다. 새 저장 키를 만들지 않았다 — 사용자 입장에선 스위치 하나로
모든 음악이 꺼지는 게 자연스럽기 때문.

## 곡은 어떻게 만들었나

`tools/generate_menu_bgm.py`가 수학으로 파형을 그려서 만든다 (난수 0 — 돌릴 때마다
완전히 같은 파일). 인게임 곡과 구분되게:

| | 인게임 bgm | 메뉴 menu_bgm |
|---|---|---|
| 빠르기 | 124 BPM | 84 BPM (느긋) |
| 파형 | square(쨍한 칩튠) + 노이즈 햇 | triangle + sine (부드러움) |
| 음량 | −10dB | −14dB (더 조용한 배경) |
| 밀도 | 8분음표 연속 | 마디당 2~3음 + 쉼표 |

루프가 "딱" 소리 없이 이어지는 비결: 마지막 음의 여운(릴리즈)이 곡 끝 **전에**
완전히 0이 되게 했고, 첫 음도 0에서 부드럽게 시작한다. 끝과 시작이 둘 다
무음이라 이음새가 안 들린다.

곡 자체는 임시(플레이스홀더)다. 진짜 곡(자작곡)이 생기면 `menu_bgm.m4a` 파일만
바꿔 넣으면 끝 — 코드는 곡 길이도 BPM도 모르기 때문이다.

## 디버그 로그로 증명하기

"안 끊긴다"를 귀로만 주장하지 않고, DEBUG 빌드에서만 찍히는 로그로 증명했다:

```
[BGMPlayer] start menu_bgm   ← 진짜로 재생이 시작될 때만
[BGMPlayer] stop menu_bgm    ← 진짜로 소리가 멎을 때만
```

화면을 4번 옮겼는데 `start`가 1번만 찍히면 = 무중단 증명 완료.
릴리즈 빌드에는 이 코드가 아예 들어가지 않는다 (`#if DEBUG`).
