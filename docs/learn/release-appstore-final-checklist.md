# 학습 노트 — 앱스토어 출시 마무리 (최종 점검)

> 2026-06-12 · 출시 직전 릴리스 전수 감사(6차원 멀티에이전트) 결과를 바탕으로 한 학습 정리.

## 앱스토어 출시가 뭐가 다른가? (Spring 비유)

Spring으로 치면 지금까지는 **로컬에서 `bootRun` 돌리고 테스트 통과시킨 상태**예요.
앱스토어 출시는 **운영 서버 배포 + 사내 보안 심사 통과**를 한 번에 하는 것과 같아요.

| iOS 출시 용어 | Spring으로 치면 |
|---|---|
| Archive (아카이브) | `./gradlew bootJar` — 배포용 산출물 굽기 |
| App Store Connect | 배포 콘솔 + 운영 대시보드 (Jenkins + 사내 포털 느낌) |
| 심사 (App Review) | 운영 배포 전 보안팀 검수 — 사람이 직접 앱을 켜서 봄 |
| Info.plist | `application.yml` — 앱의 환경설정 파일 |
| 코드 서명 (Code Signing) | 배포 산출물에 회사 도장 찍기 — 위조 방지 |
| TestFlight | 스테이징 서버 — 진짜 출시 전 베타 배포 |

## 이번 감사에서 배운 핵심 3가지

### 1. "심사 차단"은 코드 버그가 아니라 **빈 설정값**이었다

`UILayout+R9.swift:85`의 `privacyPolicyURLString = ""` — 빈 문자열 하나.
코드는 "URL이 비어 있으면 정책 버튼을 아예 안 그린다"라고 우아하게 처리했지만,
**앱이 계정을 만들고(Firebase) 이메일·이름을 수집하면 정책 링크는 법적 필수**예요.
Spring으로 치면 운영 프로파일에 `jwt.secret=` 가 비어 있는 것 — 컴파일은 되는데 운영 투입이 불가.

→ 교훈: **출시 차단은 빌드 에러 목록에 안 나온다.** 설정값·메타데이터를 따로 점검해야 한다.

### 2. "어떤 기기에 깔리는가"는 코드가 아니라 빌드 설정이 정한다

`TARGETED_DEVICE_FAMILY = "1,2"` — 1은 iPhone, 2는 iPad.
문서에는 "iPhone 전용"이라고 썼는데 설정은 iPad까지 포함이라,
이대로 제출하면 **심사관이 iPad에서 앱을 켜보고, iPad 스크린샷도 요구**돼요.
Spring의 `spring.profiles.active` 처럼 — 코드 한 줄 안 바꿔도 배포 대상이 달라지는 스위치.

### 3. 시뮬레이터에서 못 보는 것들이 있다 — "실기기 체크리스트"의 존재 이유

햅틱(진동), 전화 인터럽션, 무음 스위치, 실제 fps, Apple 로그인 왕복 —
이런 건 시뮬레이터가 흉내를 못 내요. 그래서 QA가 정직하게 "시뮬 미검증"으로
표기해 둔 항목들이 문서 4곳에 약 20개 쌓여 있었고, 출시 전 실기기 1~2세션으로 털어야 해요.
Spring으로 치면 **H2 인메모리 DB로는 못 잡는 운영 DB 이슈** 같은 것.

## 출시 절차 순서 (요약) — R13에서 코드 측 완료 (2026-06-12)

1. ~~정책 URL 호스팅 → 코드 1줄 기입~~ ✅ 노션 게시 + 기입 완료 (R13)
2. ~~권장 수정 (암호화 면제 키·런치 색상·로그 위생)~~ ✅ 완료 (R13)
   - 아이패드는 사용자 결정으로 **유지** — 시뮬레이터 QA 결과 blocker 0, 유니버설 제출 가능
   - iPadOS 26 세로 기동 축소 창 문제는 호환 키(`UIDesignRequiresCompatibility`)를 실제로
     넣어 테스트해 봤더니 **효과가 없어서 뺐다** — "넣으면 될 것 같은 키"도 실증 후 채택한다는 교훈
3. 실기기 최종 플레이 검증 (체크리스트 ~20항) ← **다음 할 일**
4. Xcode: Product > Archive → Validate → Upload
5. App Store Connect: 앱 등록·스크린샷(iPhone 6.9" + iPad 13")·설명·연령등급·개인정보 라벨·정책 URL
6. (권장) TestFlight로 본인 기기 설치 1회 → 심사 제출

상세 항목은 세션 보고서와 `REFACTOR_STATE.md` R13 진행 로그 참조.

## 덤으로 배운 것 — "키 하나도 실증"

iPadOS 26에서 세로로 앱을 켜면 가로 전용 게임이 축소 창으로 뜨는 문제가 있었어요.
인터넷 지식으로는 `UIDesignRequiresCompatibility=YES`를 plist에 넣으면 옛날 전체화면
동작이 돌아온다고 알려져 있었지만, 실제로 넣고 아이패드 시뮬레이터에서 켜 보니
화면 점유율이 똑같았어요(56.25%). 그래서 키를 빼고 제출하기로 했죠.
Spring으로 치면 — 스택오버플로에서 본 `application.yml` 설정을 그대로 믿지 않고
로컬에서 한 번 띄워 보고 반영하는 것과 같아요. **설정 변경도 코드처럼 테스트한다.**
